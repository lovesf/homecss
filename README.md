# 家庭控制台

独立的 Vite + React + TypeScript 前端，用于确认页面结构、1×1 方形 / 2×1 横向双格组件和交互。房间卡统一占 2×1。基础格子为 146px（原 168px 的 87%，文字保持正常大小），间距 10px，屏幕变宽只增加列数；可在“设置 → 显示 → 格子大小”整体缩放 80%–120%（滑杆或 −/+ 按钮按 1% 调整，所有屏幕共用，存于服务设置 `tileScale`），格子、间距与卡片内的文字、按钮一起按比例缩放（卡片按 146px 基准排版后用 CSS `scale` 缩放，拖动位移用独立的 `translate`，不受缩放影响）；极窄屏只有一列时，双格卡暂按单格显示。手机宽度（≤720px）例外：列数照常按格子宽度计算，但各列平分铺满整行（卡片与标题左右对齐），行高保持格子高度；房间页标题旁的“N 盏灯亮”与顶部状态标签重复，手机上隐藏。数据来源由 `server/` 下的 Python 控制台服务决定：演示模式使用 `src/mockHome.ts`，操作只改浏览器内存；Home Assistant 模式由服务自动发现 HA 中的房间与设备（见下文）。

空调模拟数据按现有 HA 实体的能力设置：模式支持自动、制热、除湿、送风、制冷，风速支持自动、低、中、高；两组均把自动显示在第一项。地暖只有制热模式，不显示风速设置。温控卡片左上角的模式图标就是电源开关（与灯一致：关闭为灰色，打开时按模式着色），右上角显示房间名（首页常用 / 正在运行中）；2×1 时名称与简短状态（制冷 / 已关闭 / 不可用）放在图标右侧，与灯一致，温度下方只补充室温和风速，右下为 +/−；1×1（以及单列窄屏）不放 +/−，底部左侧为名称与简短状态、右侧为大号温度。有二级弹窗的卡片（温控卡片、1×1 可调灯）点按钮、滑杆以外的任意位置即打开详情（温控为调温和切换模式，灯为亮度、色温、颜色）；电源按钮的触摸范围向外扩约 10px，按钮附近都归按钮；编辑布局时不响应。演示模式下的更改仍只影响模拟状态。

灯光使用独立的 `LightCard`：`onoff` 仅开关；可调灯支持 1×1 和 2×1 两种布局。1×1 卡片只直接提供开关，其余亮度、色温、颜色集中在一个设置弹窗；2×1 仍直接显示亮度、色温滑杆。没有可调项的灯不弹出设置。模拟控制值用百分比和十六进制颜色表示，正式接入 HA 时仍需转换为它的原生亮度和颜色参数。

房间内卡片不重复显示房间名。灯的亮度和色温滑杆使用更粗的轨道及更大的拖动手柄；调色按钮会打开自制弹窗，提供白色、暖白、冷白预设，以及以白色开头的常用色和连续色板。点击预设、色块或色板一次即应用并关闭弹窗，不调用系统颜色选择器。滑杆以暖色和冷暖渐变区分，视觉上省略“亮度”“色温”文字，但保留屏幕阅读器可识别的名称。

房间页点击“编辑布局”后，可用鼠标拖动整张卡片，或在触屏上拖动右上角把手来调整顺序；支持两种尺寸的卡片可点右下角按钮切换 1×1／2×1。编辑时把手左侧的星标用于加入或移出我的家庭“常用设备”（☆ 未加入，★ 已加入），新加入的排在末尾。我的家庭页“常用设备”标题旁的“编辑”可拖动调整常用顺序、点右下角按钮切换 1×1／2×1、点 ★ 移出；常用区尺寸与房间内尺寸分开保存（存于 `sizes` 中 `favorites/<实体 id>` 键），未设置时用设备默认尺寸。未设置过时默认为客厅空调、背景灯、AppleTV。侧栏房间列表末尾的“房间排序”（平板为图标栏、手机为底部标签栏的最后一项；只读模式隐藏）打开排序弹窗：房间与其他空间分组内拖动把手或点上移 / 下移调整，改动立即生效，“恢复默认”回到自动发现 / 演示数据的原顺序；侧栏和“正在运行”里同类按房间排序都使用这个顺序。布局（尺寸、顺序、常用设备、房间顺序）保存在控制台服务的 `server/data/layout.json`，全家所有屏幕共用，一处修改其他已打开的页面立即同步；浏览器只缓存上次的布局用于首屏显示。点“完成”退出编辑。

我的家庭顶部只显示当前有活动的摘要：有人在家、亮灯、运行中的空调或地暖、有门窗打开、有安全告警时才出现对应标签，不显示 0 或运行数／总数。房间顶部共用无背景的状态标签，只显示有活动或异常的状态，依次为异常报警（只有水浸、烟雾）、有灯点亮时的数量、温湿度、有人（同一房间的人体移动 / 存在传感器合并，任意一个检测到即为有人；无人时不显示，全部状态未知时提示）、打开着的门窗、正在运行或不可用的空调/地暖（关闭的不显示），最后才是低电量或电池状态未知的警告；一个标签都没有时整行隐藏。温湿度、移动、门磁、水浸和烟雾不占设备格子；门磁只在开门时以普通状态标签提示（不算告警，侧栏也不出红点）。设备格子只保留可操控的灯、温控和播放器。`MediaPlayerCard` 为 Apple TV 与 HomePod 提供模拟播放操作，按钮按模拟能力显示；实际 HA 支持的操作尚未校验。低电量阈值暂定为 20%。

视觉采用低反光深色分层表面：颜色变量集中在 `src/styles.css` 顶部 `:root`，房间图标、灯光光晕色、温控模式配色在 `src/appearance.ts`，强调色可在“设置 → 显示 → 主题”下选择琥珀（默认）、珊瑚、玫瑰、紫罗兰、天蓝、青绿、草绿，所有屏幕共用（服务设置 `accent`，页面根元素 `data-accent`，深浅主题各一套变量，定义在 `src/theme.ts` 与 `styles.css`）；灯光光晕、亮度条、冷暖与告警色按含义保持不变。问候语与时钟格式在 `src/time.ts`（页头左上角是按时段挑选的一句话，周末另有句子，同一天同一时段固定不变；宽屏侧栏已有日期，平板窄栏和手机才在句子后补日期）。开启的灯按当前颜色或色温、以亮度决定强度着色；空调按制冷蓝、制热橙、除湿青、送风灰着色，地暖为橙色。我的家庭页在“常用设备”下方是“正在运行”：已打开的空调、地暖、灯，以及播放中/已开机的播放器，按此顺序排列，同类按房间顺序；卡片标出所属房间，统一用单格（播放器只能双格）。已在常用设备里的不再重复列出（常用卡片本身显示开关状态），标题数字仍是全屋运行总数，旁边注明其中几个在常用设备中，全部都在常用里时不显示卡片。标题右侧“全部关闭”只关这一区列出的灯、空调、地暖（播放器与常用设备不动），需在 3 秒内再点一次“确认关闭 N 个”才执行；只读模式隐藏。在这里关掉的设备先留在原位（显示为关闭，可再打开），3 秒后自动移出；3 秒内重新打开则保留；新打开的设备会立即加入。导航不再有单独的“房间”列表页：侧栏依次为我的家庭和展开的各房间（不设单独的家人页，谁在家只在我的家庭顶部摘要显示）（含“其他空间”），点房间直接进入；有设备运行的房间带暖色圆点，有告警则为红点。宽屏为带时钟的侧栏，平板为窄图标栏，手机改为可横向滑动的底部标签栏，弹窗在手机上以底部面板出现。

设置页分“连接”“设备”“自动化”“显示”“安全”“记录”六个标签（方向键可切换）。入口在侧栏时钟右侧（平板在时钟下方，手机在页面右上角）的齿轮进入：点击后弹出数字键盘输入 4 位管理密码（实体键盘也可直接输入数字、退格），默认 `1234`，输满 4 位由控制台服务验证；连续输错 5 次锁定 60 秒，之后每次翻倍、最长 15 分钟。验证通过后服务下发 HttpOnly 会话 Cookie（空闲 10 分钟失效），离开设置页即退出。页面内可以：开关“允许控制设备”（关闭后所有屏幕只读，服务也拒绝控制与布局修改）；在“演示数据 / Home Assistant”之间切换；填写 HA 地址与长期访问令牌；修改管理密码；在“显示”中设置首页标题（同时作为导航中的首页名称，最多 12 字）和副标题（最多 60 字，留空不显示）；查看最近的操作记录。这些都是全局设置，由服务保存，所有屏幕一致。

连接 Home Assistant：浏览器只连接控制台服务（`/api/ws`、`/api/*`），从不接触令牌。服务用令牌持有唯一的 HA WebSocket 连接，不绑定固定设备清单，而是自动发现：房间取自 HA 区域（实体区域优先，其次所属设备的区域；都没有时名称以某区域名开头的按“区域-设备”规范归入该区域，否则进“未分配区域”）；设备卡为 HA 中的灯、温控（只有制热的算地暖）、播放器；温湿度、门窗、人体、水浸、烟雾传感器进顶部摘要，电量传感器进电池提醒，HA 人员（person）进在家状态。温湿度按 HA 实体的显示精度格式化（HA 中手动设置的优先，其次集成建议的，例如原始状态 27.700006 显示为 27.7）；没有精度时温度最多 1 位小数、湿度取整。HA 中隐藏、禁用或属于配置 / 诊断类别的实体不参与发现；HA 的区域、设备、实体注册表变化后自动重新发现。设置页“设备筛选”列出全部发现的实体，可选黑名单（默认，全部显示，勾选的加入黑名单不显示）或白名单（勾选的加入白名单才显示），两种模式互斥，只有当前模式的名单生效；另一份名单保留但不起作用，切回时恢复。页面按实体请求控制，服务只放行当前可见实体的 `light.turn_on/turn_off`、`climate.set_hvac_mode/set_temperature/set_fan_mode`、`media_player.turn_on/turn_off/media_play_pause/volume_set` 及其合法参数。不可用的设备显示为不可用；HA 断线时由服务自动重连。页面与控制台服务之间断线（例如手机锁屏、切换网络）时保留最后一次的状态继续显示，不清空也不立即报错：20 秒内顶部显示“正在重新连接…”，超过才提示“连接中断，显示某时刻的状态”；页面回到前台、网络恢复或从缓存恢复时立即重连（后台超过 15 秒则直接重建连接），另有每 25 秒一次的 ping/pong 心跳，5 秒无回应即判定连接失效并重连；收到新快照后恢复实时状态。HA 模式的目录与状态每 2 秒最多写一次浏览器缓存（页面转入后台时立即写入，12 小时内有效），页面被系统回收后重新打开先显示缓存。断线期间的操作会回退并提示“操作未发送”；已发出但未收到结果的提示“结果未知”，以重连后的设备状态为准。操作先乐观更新页面，并记录本次操作的目标值（开关、模式、温度、亮度等）：HA 确认一致前推来的旧状态不覆盖这些值（其他数值如室温照常更新），避免云端设备确认较慢时开关先跳回再跳过去的闪烁；确认后以 HA 为准，10 秒仍未确认则显示 HA 的实际状态，调用失败会回退并在底部提示；滑杆与连续调温合并 300ms 后发送。需要在终端核对某台 HA 的发现结果时，运行只读诊断 `uv run python -m home_console_server.inspect`（只读取注册表与状态，不调用服务、不输出令牌）。

天气（和风天气）：侧栏“我的家庭”下方为“天气”页，显示实时天气（温度、体感、湿度、风、降水、气压、能见度、紫外线、日出日落）和未来 7 天预报（每天的最低/最高温按本周范围画成温度条）；我的家庭页标题右侧显示当前天气摘要，点击进入天气页。位置可输入城市、区县搜索，或点“使用当前位置”由浏览器定位（需要 HTTPS 或本机地址，否则浏览器不允许定位）；未选择过时使用 HA 中“家”（zone.home）的位置。位置每块屏幕各自记在浏览器中。浏览器只请求控制台服务的 `/api/weather*`，由服务向和风天气查询：密钥与 API Host 在设置页“连接 → 和风天气”中填写（密钥加密保存、不发给浏览器，可点“测试”确认），修改后立即生效；设置为空时服务才使用环境变量 `QWEATHER_API_KEY` / `QWEATHER_API_HOST` / `QWEATHER_GEO_HOST`（仅供开发测试）。服务端缓存天气 10 分钟、城市搜索 1 天，页面每 10 分钟及回到前台时刷新。

主题：设置页“显示 → 主题”可选浅色、深色、自动，所有屏幕共用（服务通过状态消息下发）。自动为日出到日落使用浅色、其余时间深色，日出日落取该屏幕所选位置当天的天气预报，没有天气时按 06:00 与 18:00；每 15 秒随时钟重新判断。颜色变量集中在 `src/styles.css` 顶部，浅色主题在 `:root[data-theme="light"]` 中覆盖；页面打开时先用浏览器记住的上次主题，避免首帧闪烁。

状态标签：首页的“N 盏灯亮”“N 台空调开启”“N 处地暖开启”和房间页的亮灯、空调 / 地暖标签可以点击，弹出当时开着的设备列表（首页按房间分组），每项显示亮度 / 色温或模式 / 设定温度，可逐个开关；底部“全部关闭”只对仍开着的设备发送关闭（灯 `light.turn_off`，空调 / 地暖设为 `off`），已关闭的不重复发送。列表以打开那一刻为准，关掉的设备留在原位可再打开；只读模式只显示状态。

上下滑动切换：在右侧内容区（页头或下方内容）上下滑动可按左侧导航顺序切换页面（我的家庭 → 各房间 → 其他空间）。页面已在顶部时继续下拉进入上一个，已在底部时继续上滑进入下一个，内容不足一屏时两个方向都可以；滑动时不显示文字提示，内容跟随手指略微位移；拖动超过 8px 开始计算，超过 60px 松手即切换（判断“已在底部”留 6px 容差，避免 iOS 回弹时误判）。设置页、编辑布局、弹窗打开时不启用，从滑杆或输入框开始的滑动不处理；页面禁用了浏览器的下拉刷新。

安装为应用（PWA）：`public/manifest.webmanifest` 提供应用名称、全屏（standalone）打开方式与图标；`index.html` 另有 iOS 所需的 `apple-touch-icon` 与 `apple-mobile-web-app-*` 标签（状态栏透明、内容延伸到顶部，页头与导航按 `env(safe-area-inset-*)` 留出状态栏和刘海；浅色主题下 iOS 独立运行时在状态栏后垫深色条，保证白色状态栏文字可读）。图标由 `tools/make_icons.py`（纯标准库）生成：`icons/icon-192/512.png`、Android 自适应图标 `icons/maskable-512.png`、`apple-touch-icon.png`。`public/sw.js` 只在 HTTPS 或本机地址下注册：`/api` 从不缓存；页面入口先取网络最新版本、离线才用缓存；`/assets/` 下带哈希的构建文件缓存优先。**Android（Chrome）要通过 HTTPS 访问才会作为应用安装**，HTTP 局域网地址只能添加普通快捷方式；iOS Safari 的“添加到主屏幕”在 HTTP 下也能全屏打开（未在真机上验证），但离线缓存同样需要 HTTPS。

开发时需要同时运行前端和控制台服务（Vite 会把 `/api` 转发到 `127.0.0.1:8765`）：

```bash
npm install
npm run dev
```

```bash
cd server && uv sync && uv run python -m home_console_server
```

`npm run build` 用于类型检查和生产构建。构建后控制台服务可以直接提供页面：`uv run python -m home_console_server --host 0.0.0.0`，访问 `http://<主机>:8765/`。可用环境变量 `HOME_CONSOLE_HOST`、`HOME_CONSOLE_PORT`、`HOME_CONSOLE_DATA`（数据目录）、`HOME_CONSOLE_SECRET`（令牌加密密钥，Fernet 格式）调整。

控制台服务数据（均为本地文件，目录 0700、文件 0600）：`server/data/settings.json`（HA 地址、控制开关、数据来源、设备筛选、管理密码 scrypt 哈希、加密后的令牌）、`secret.key`（未设置 `HOME_CONSOLE_SECRET` 时自动生成的加密密钥）、`layout.json`（共用布局）、`audit.log`（登录、设置、布局、设备控制记录，超过 1MB 轮转；不含令牌和密码）。与 Node-RED 同理，能读取整个数据目录的人仍可解密令牌；把密钥放到环境变量可以让数据文件单独泄露时不暴露令牌。

页面访问 Vite 输出的地址（开发）或控制台服务地址（构建后）。

代码分层：`src/useConsole.ts` 与 `src/consoleClient.ts` 连接控制台服务，`src/consoleApi.ts` 封装管理与布局接口；`src/useHome.ts` 持有家庭状态并提供全部设备操作（`DeviceActions`），能力校验在 `src/deviceCommands.ts`，HA 状态转换与服务调用翻译在 `src/haAdapter.ts`；后端在 `server/home_console_server/`（`app.py` 接口与白名单、`discovery.py` 自动发现与过滤、`ha.py` HA 连接、`store.py` 本地文件、`auth.py` 会话与限流）；`src/selectors.ts` 放筛选、运行判断与排序规则；`src/useTileDrag.ts` 负责编辑布局时的拖动排序；`src/layout.ts` 负责卡片尺寸规则与 localStorage。`App.tsx` 只组合页面，设备卡在 `src/components/`，由 `DeviceCard` 按类型分发到灯、温控、播放器卡片。

设置 → 自动化：同步 HA 的自动化列表（`automation.*`，注册表中禁用的不列出），显示开关状态和上次触发时间，可逐个开启或关闭；服务只调用 `automation.turn_on` / `turn_off`，只接受当前列表中的实体，只读模式下拒绝，每次切换写入操作记录；打开期间每 5 秒刷新一次。演示模式为服务内存中的几条演示自动化。接口为 `GET/PUT /api/admin/automations`（需管理登录），实现见 `server/home_console_server/automations.py` 与 `src/components/AutomationList.tsx`。

设置 → 自动化 → 季节规则（默认关闭）：启用后，控制台用 HA 令牌（需管理员权限）在 HA 中创建并维护辅助元素 `input_select.home_console_season`（控制台-季节，选项 夏季 / 冬季，为唯一的季节状态）和三条自动化：`automation.home_console_season_heating_off`（夏季地暖一打开就关闭，切到夏季时关闭全部地暖）、`automation.home_console_season_ac_summer`（夏季空调从关闭开成制热时改为制冷）、`automation.home_console_season_ac_winter`（冬季空调从关闭开成制冷时改为制热）；送风、除湿等不处理。地暖与空调按支持的模式自动识别（只有制热 / 关闭为地暖，同时支持制冷和制热为空调），设备变化时自动更新；HA 按中文名生成的拼音实体 ID 会按 unique_id 改为上述固定 ID；关闭季节规则时删除三条自动化、保留辅助元素；每次同步写入操作记录。季节在设置里手动切换，“我的家庭”标题后显示季节标志；页面也配合：夏季地暖卡片显示“夏季停用”且点不开，打开空调时直接用当季模式。演示模式季节保存在控制台设置中，不改动 HA。实现见 `server/home_console_server/season.py`。同一个 HA 只应由一个控制台启用季节规则。

真实设备联调时，先在“设备筛选”确认发现结果与房间归属，可先关闭“允许控制设备”只读观察，再逐个验证控制与状态回写。
